# Word 选区发送到对话 — 架构设计方案

> 状态：设计中 | 目标：在 Word 原生渲染视图中，选中文字后发送引用到 WFM Chat

## 1. 需求描述

在 WFM Studio 中打开 Word 文件后，用户选中一段文字，通过浮动工具栏将选区以结构化引用的形式发送到 WFM Chat 对话框中。Agent 收到后可基于选区内容回答问题。

交互体验对标 Cursor 的 `@file` 引用机制，但面向业务人员，必须保留 Word 原生排版。

## 2. 整体架构

│  │  每个 <p> 注入 data-para-index                │    │
│  │                                             │    │
│  │  用户选中文字 → 浮动按钮「发送到对话」         │    │
│  └──────────────┬──────────────────────────────┘    │
└─────────────────┼───────────────────────────────────┘
                  │ postMessage
                  ▼
┌─────────────────────────────────────────────────────┐

│  └─ 调用 WFM Chat Service 推送到对话                  │
└─────────────────┬───────────────────────────────────┘

## 3. 核心模块

### 3.1 Word 原生渲染器（CustomEditorProvider + Webview）

- 注册 `.docx` 文件的 `CustomEditorProvider`
- Webview 内用 docx-preview 渲染，保留完整排版、样式、表格
- 渲染完成后，遍历 DOM 给每个段落元素注入 `data-para-index`
- 已有成熟开源库支撑，风险可控

### 3.2 选区追踪 + 浮动操作栏（Webview 内 JS）

- 监听 `selectionchange` / `mouseup`，通过 `window.getSelection()` 获取选区
- 从选区的 `anchorNode` / `focusNode` 向上查找带 `data-para-index` 的父元素，得到起止段落号
- **不使用右键菜单**（Webview 内实现右键菜单体验差），改为选中文字后弹出浮动工具栏，类似 Google Docs / 飞书文档的体验
- 浮动栏包含一个按钮：「发送到对话」

### 3.3 数据结构体

```typescript
interface DocumentReference {
  fileName: string;          // "审图规范.docx"
  filePath: string;          // URI，用于 Agent 回读原文
  startPara: number;         // 起始段落索引
  endPara: number;           // 结束段落索引
  selectedText: string;      // 选中的文字原文
  displayLabel: string;      // 展示用："审图规范.docx · 第3-5段"
}
```

对外展示用「第X-Y段」而不是行号——段落是 Word 文档的稳定结构单元，不会因窗口大小/字体变化而漂移。

如果文档有标题层级，可进一步显示为 `审图规范.docx · 3.2节 · 第1-3段`，体验更好。

### 3.4 Chat 面板集成

- `wfmAgentClientService` 新增 `sendDocumentReference(ref)` 方法
- Chat 输入区域渲染引用卡片：文件名 + 段落范围 + 文字预览
- 卡片可点击，跳回文档对应段落位置（滚动定位）
- 用户在卡片下方输入问题，Agent 拿到 `{文件路径, 段落范围, 选中文本}` 作为上下文

## 4. 关键设计决策

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 选区粒度 | 段落索引 | Word 的行号不稳定，段落是 OOXML 的原生结构单元 |
| 交互方式 | 浮动工具栏 | 比右键菜单更直觉，业务用户无需学习 |
| 引用展示 | `文件名 · 第X-Y段` | 直观可读，点击可跳转回原文 |
| 段落标记方式 | DOM data-attribute | 轻量，不侵入文档内容 |

## 5. 主要风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| docx-preview 对复杂排版渲染不完整 | 表格嵌套、文本框、SmartArt 可能丢失 | 用实际业务文档做兼容性验证，必要时 patch 库 |
| 选区跨表格/列表的边界情况 | 段落索引映射可能不准确 | 对复杂结构做 fallback，取最近祖先段落 |
| 浮动工具栏定位精度 | 可能遮挡内容或超出视口 | 计算选区 BoundingRect + 视口边界检测 |

## 6. 分期计划

### MVP（第一期）

- docx 渲染（CustomEditorProvider + docx-preview）
- 段落索引注入（简单递增编号）
- 选区追踪 + 浮动工具栏
- 推送到 Chat，以引用卡片展示

### 增强（第二期）

- 解析 Word 标题层级，引用展示升级为 `X.X节` 格式
- 支持表格单元格级粒度
- 引用卡片点击跳转回文档对应位置
