# WFM Studio 办公文档技能 — 测试用例场景

> **版本**：v0.2（2026-05-23）
> **目的**：为 Claude Code Skills / MCP Server 办公文档能力设计可落地的测试场景，覆盖标书、预算、方案、PPT、金额核对五大场景。
> **约定**：所有输入/输出文件均位于 `WFM_WORKSPACE_ROOT` 工作区内。

---

## 支持状态总览

基于项目代码审计（2026-05-23），各场景当前支持情况：

| # | 场景 | 支持状态 | 缺口说明 |
|---|------|---------|---------|
| TC-1 | 标书金额核对 | **已支持** | `docx_read` MCP 工具 + `extract_amounts_from_table` 已实现，Claude 可自主核对 |
| TC-2 | 标书一键生成 | **不支持** | `ARCH_DOC_GENERATION.md` 仅为规格，5 步 pipeline 无代码实现，无 `docx_write` 工具 |
| TC-3 | 工程预算编制 | **不支持** | 无 xlsx 读取能力（无 openpyxl 依赖、无 MCP 工具），无 `xlsx_read` 工具 |
| TC-4 | 技术方案编写 | **部分支持** | CAD 读取（15 个工具）+ DOCX 读取已实现，但无 `docx_write` 写回能力 |
| TC-5 | 汇报 PPT 生成 | **不支持** | 无 pptx 相关代码（无 python-pptx 依赖、无 MCP 工具） |
| TC-6 | DOCX 选区追问 | **已支持** | 选区→浮动工具栏→Chat 链路已完整实现，含段落范围语义化 |
| TC-7 | 多文档对比审阅 | **部分支持** | `docx_read` 可分别读取两份文档，Claude 可自行对比；但无专用 diff 工具 |

**已实现的办公能力**：
- `docx_read` MCP 工具 — 解析 .docx 为结构化 Markdown（段落 + 表格 + 金额提取）
- DOCX Viewer 前端 — docx-preview 渲染 + 选区追踪 + 浮动工具栏 + 发送到对话
- Explorer 右键菜单 — "发送到 Chat"（任意文件）+ "AI 金额核对"（.docx）

**缺失的办公能力**：
- `xlsx_read` / `xlsx_write` — xlsx 读写（需 openpyxl）
- `docx_write` — docx 写回/创建（需 python-docx 写入能力）
- `pptx_create` — pptx 生成（需 python-pptx）
- 标书生成 pipeline — 5 步 AI 工作流（大纲→撰写→评审→格式化）

## TC-1：标书金额核对

### 场景描述

审图工程师收到一份投标文件，需要核对其中所有报价表格的金额计算是否正确。

### 输入

**文件**：`docs/samples/投标文件_v3.docx`

文档包含以下内容结构：

```
投标文件 — 船用管路系统采购项目

第1章 投标函
  （略）

第2章 报价明细表
  表2-1 管材报价
  | 序号 | 名称         | 规格       | 单位 | 数量 | 单价(元) | 合价(元)   |
  |------|-------------|-----------|------|------|---------|-----------|
  | 1    | 无缝钢管     | φ89×4.5   | 吨   | 12   | 8,500   | 102,000   |
  | 2    | 不锈钢管     | φ60×3     | 吨   | 5    | 28,000  | 140,000   |
  | 3    | 紫铜管       | φ22×1.5   | 千克 | 200  | 85      | 17,000    |
  | 小计 |              |           |      |      |         | 259,000   |

  表2-2 阀门报价
  | 序号 | 名称         | 规格        | 单位 | 数量 | 单价(元) | 合价(元)  |
  |------|-------------|------------|------|------|---------|----------|
  | 1    | 蝶阀         | DN100-PN16 | 个   | 20   | 1,200   | 24,000   |
  | 2    | 截止阀       | DN50-PN25  | 个   | 35   | 650     | 22,750   |
  | 3    | 止回阀       | DN80-PN16  | 个   | 15   | 980     | 14,700   |  ← 实际应为 14,700，但文档写的是 14,000（故意错误）
  | 小计 |              |            |      |      |         | 60,050   |  ← 实际应为 61,450

  报价总计：319,050 元  ← 实际应为 320,450 元

第3章 技术规格响应
  （略）
```

**用户消息**：`核对这份投标文件中的所有金额`

### 期望输出

Agent 应通过 `docx_read` MCP 工具解析文档，输出结构化核对报告：

```markdown
## 金额核对报告 — 投标文件_v3.docx

### 表2-1 管材报价
| 序号 | 名称     | 数量 | 单价     | 合价(文档) | 合价(计算)   | 结果 |
|------|---------|------|---------|-----------|-------------|------|
| 1    | 无缝钢管 | 12   | 8,500   | 102,000   | 102,000     | ✅   |
| 2    | 不锈钢管 | 5    | 28,000  | 140,000   | 140,000     | ✅   |
| 3    | 紫铜管   | 200  | 85      | 17,000    | 17,000      | ✅   |
| 小计 |         |      |         | 259,000   | 259,000     | ✅   |

### 表2-2 阀门报价
| 序号 | 名称   | 数量 | 单价   | 合价(文档) | 合价(计算)  | 结果 |
|------|-------|------|-------|-----------|------------|------|
| 1    | 蝶阀   | 20   | 1,200 | 24,000    | 24,000     | ✅   |
| 2    | 截止阀 | 35   | 650   | 22,750    | 22,750     | ✅   |
| 3    | 止回阀 | 15   | 980   | **14,000**| 14,700     | ❌ 差额: -700 |
| 小计 |       |      |       | **60,050**| 61,450     | ❌ 差额: -1,400 |

### 全局汇总
| 项目       | 文档金额   | 计算金额   | 结果 |
|-----------|-----------|-----------|------|
| 管材小计   | 259,000   | 259,000   | ✅   |
| 阀门小计   | **60,050**| 61,450    | ❌   |
| **总计**   | **319,050**| 320,450  | ❌ 差额: -1,400 |

### 问题清单
1. ❌ 表2-2 第3行「止回阀」：15 × 980 = 14,700，文档值为 14,000，差额 -700
2. ❌ 表2-2 小计：应为 61,450，文档值为 60,050，差额 -1,400
3. ❌ 全局总计：应为 320,450，文档值为 319,050，差额 -1,400
```

### 验收标准

- [ ] `docx_read` 工具被正确调用，解析出 3 个表格
- [ ] 逐行验证 数量 × 单价 = 合价，标注 ✅/❌
- [ ] 逐表验证 小计 = 行合价之和
- [ ] 全局验证 总计 = 各表小计之和
- [ ] 发现 3 处计算错误并准确定位到行号

### 当前支持分析

**状态：已支持，可直接测试**

已实现的能力：
- `docx_read` MCP 工具 — 调用 `parse_docx()` 解析段落和表格，返回 Markdown
- `extract_amounts_from_table()` — parser 内置金额提取函数，识别千分位、货币符号
- Explorer 右键菜单 "AI 金额核对" — 直接触发金额核对场景
- Claude system prompt 中包含 DOCX 审阅能力说明

**可执行的测试路径**：
1. 将 `投标文件_v3.docx` 放入工作区
2. 在 IDE 中右键 → "AI 金额核对"，或在 Chat 中输入 `核对 投标文件_v3.docx 中的所有金额`
3. Claude 调用 `docx_read` → 解析表格 → 逐行核对 → 输出报告

**风险点**：Claude 的核对准确率取决于模型能力，千分位数字（如 `8,500`）的解析可能有误。

## TC-2：标书一键生成

### 场景描述

商务人员拿到一份招标需求说明书，需要一键生成完整的投标文件。

### 输入

**文件 1**：`docs/samples/招标需求说明书_船用管路系统.docx`

```
招标需求说明书

项目名称：船用管路系统采购项目
项目编号：ZB-2026-0342
招标单位：XX造船厂

一、项目概况
  本项目为某型散货船管路系统采购，包含管材、阀门、法兰及附件。

二、采购范围
  1. 无缝钢管、不锈钢管、紫铜管等管材
  2. 蝶阀、截止阀、止回阀、安全阀等阀门
  3. 平焊法兰、对焊法兰等连接件
  4. 管路支架、吊架等附件

三、交付要求
  交付时间：合同签订后 60 天
  交付地点：XX造船厂码头仓库
  质保期：验收合格后 24 个月

四、资质要求
  1. 具有 CCS（中国船级社）工厂认可
  2. ISO 9001 质量管理体系认证
  3. 近三年同类项目业绩不少于 3 个

五、评标方法
  综合评分法（商务 30% + 技术 50% + 价格 20%）

六、投标文件要求
  投标文件应包含：
  - 投标函
  - 法定代表人授权书
  - 报价明细表
  - 技术规格响应表
  - 资质证明文件
  - 业绩证明
  - 售后服务方案
```

**用户消息**：`根据这份招标需求说明书，生成一份完整的投标文件。输出为 docx 格式。`

### 期望输出

**文件**：`output/投标文件_船用管路系统.docx`

文档结构：

```
投标文件 — 船用管路系统采购项目 (ZB-2026-0342)

第1章 投标函
  致：XX造船厂
  我方确认参与本次招标...

第2章 法定代表人授权书
  ...

第3章 报价明细表
  表3-1 管材报价
  表3-2 阀门报价
  表3-3 法兰及附件报价
  报价汇总表

第4章 技术规格响应表
  逐项响应招标文件中的技术要求...

第5章 资质证明文件
  5.1 CCS 工厂认可证书
  5.2 ISO 9001 认证
  ...

第6章 业绩证明
  近三年同类项目业绩清单...

第7章 售后服务方案
  7.1 质保承诺
  7.2 响应时间
  7.3 备品备件
  7.4 培训计划

第8章 项目实施计划
  8.1 生产进度
  8.2 质量控制
  8.3 交付方案
```

### 验收标准

- [ ] 生成大纲阶段输出 JSON 结构（章节名 + 内容要点）
- [ ] 输出 docx 文件可被 Word/WPS 正常打开
- [ ] 章节覆盖招标文件要求的全部内容（投标函、授权书、报价表、技术响应、资质、业绩、售后方案）
- [ ] 报价表包含完整的表格结构（序号、名称、规格、单位、数量、单价、合价）
- [ ] 技术规格响应逐项对应招标文件中的采购范围
- [ ] 文件大小 > 50KB（非空文档）
- [ ] 生成过程中 IDE 显示进度（大纲→撰写→评审→格式化）

### 当前支持分析

**状态：不支持，需新增 3 个核心能力**

缺失的能力：
1. **`docx_write` MCP 工具** — 当前只有 `docx_read`，无法创建/写入 docx 文件。`python-docx` 已是后端依赖（用于解析），但写入能力未封装为 MCP 工具
2. **标书生成 pipeline** — `ARCH_DOC_GENERATION.md` 描述了 5 步工作流（大纲→撰写→评审→格式化），但无代码实现
3. **前端 docGen UI** — 无 `contrib/wfm/docGen/` 目录，无生成进度面板

**替代方案（当前可跑通）**：
- Claude 可通过 `workspace_write` 将 Markdown 内容写入 `.md` 文件
- 用户再手动将 Markdown 转为 docx（如通过 Pandoc）
- 但这不是"一键生成 docx"的完整体验

**需要新增**：
- `docx_write` MCP 工具（基于 python-docx 创建文档，支持标题/段落/表格）
- `proposal_outline` / `proposal_write_section` / `proposal_review` 工具链
- 前端生成进度 UI（可选，首期可用 Chat 流式输出替代）

### 当前支持分析

**状态：不支持，需新增 xlsx 读取能力**

1. **`xlsx_read` MCP 工具** — 项目中无 openpyxl 依赖，无 xlsx 相关代码。`docx_read` 只支持 .docx
2. **`docx_write` MCP 工具** — 输出预算书需要创建新 docx（同 TC-2 缺口）
3. **两表关联计算** — 需要 Claude 理解"工程量清单 × 单价表 = 预算"这个计算逻辑

**需要新增**：
- `openpyxl` 依赖到 `pyproject.toml`
- `xlsx_read` MCP 工具（读取工作表、表头、数据行，输出为 Markdown 表格）
- `docx_write` MCP 工具（同 TC-2）

**降级方案**：如果先将 xlsx 转为 CSV，Claude 可通过 `workspace_read` 读取 CSV 并计算。但需要用户手动转换，不是理想体验。

## TC-4：技术方案编写

### 场景描述

技术工程师拿到技术规格书和 CAD 图纸，需要编写一份施工技术方案。

### 输入

**文件 1**：`docs/samples/技术规格书_管路安装.docx`

```
技术规格书 — 某型散货船管路安装

1. 适用范围
   本规格适用于机舱区域管路系统的预制与安装。

2. 管材要求
   - 碳钢管：符合 GB/T 8163，材质为 20# 钢
   - 不锈钢管：符合 GB/T 14976，材质为 316L
   - 管路系统设计压力：1.6 MPa
   - 管路系统设计温度：≤ 200°C

3. 安装要求
   - 管路布置应满足船级社规范
   - 法兰连接螺栓预紧力矩符合 CB/T 3766
```

### 当前支持分析

**状态：部分支持（可手动触发，无专用工具）**

已实现的能力：
- `docx_read` 可分别读取两份 .docx 文件，返回结构化 Markdown
- Claude 具备文本对比能力，可自行分析差异

缺失的能力：
- **`docx_diff` MCP 工具** — 无专用 diff 工具，Claude 需要两次调用 `docx_read` 然后自行对比
- **结构化 diff 输出** — 无标准化的差异 Schema（修改/新增/删除分类）
- **多文件关联** — 当前 Chat 附件机制不原生支持"对比模式"（一次选两个文件并声明为对比关系）

**可执行的降级测试**：
1. 在 Chat 中输入 `对比 标书_初稿.docx 和 标书_修订稿.docx，列出所有差异`
2. Claude 先后调用 `docx_read` 读取两份文件
3. Claude 自行对比并输出差异报告

**风险点**：长文档对比时，两次 `docx_read` 的输出可能接近上下文窗口限制；表格行的对比准确率取决于模型。

## 实现优先级建议

基于使用频率和技术依赖关系，建议按以下顺序实现缺失能力：

| 优先级 | 能力 | 新增 MCP 工具 | 新增依赖 | 覆盖场景 |
|--------|------|--------------|---------|---------|

P0 实现后，TC-1/TC-6 可直接测试；TC-2/TC-3/TC-4 可降级测试（输出 Markdown 而非 docx）。
P0+P1 实现后，TC-3 可完整测试。
P0+P2 实现后，TC-5 可完整测试。
